## 0. この文書の使い方

- 別の Claude セッションに貼り付けて使う前提で書いています。そのセッションからは Mac のファイルを見られないので、必要な設計・文言・判定ルールは本文に含めました。
- 「✅ 検証済み」はモックで実測・テスト済みのもの、「⚠ 要実機確認」は公開アプリ（タブレット）で初めて確かめる必要があるものです。

## 1. 目的

生徒と短い雑談（聞き役）を音声で行う。テスト結果の聞き取りの前のアイスブレイク、または聞き取り本体の土台にする。

「自然に話せている」の定義：

- 沈黙を作らない（生徒が話し終えた瞬間に何か声が出る）
- 日本語のアクセントが正しい
- 生徒の番を奪わない（生徒が答える前に次へ進まない）

## 2. 推奨構成（タブレットで使う公開アプリ版）

```
[タブレットのブラウザ（Safari 本体）]
  🎤 押して話す → 音声認識（webkitSpeechRecognition）→ 文字
      │
      ├─ ① 場面を判定（端末内・一瞬）→ つなぎ言葉の音声を即再生（事前に作った音声ファイル）
      │
      └─ ② サーバー API
           ├─ /api/voice-chat → Claude Sonnet 5 で返事の文を作る（API キーはサーバー側だけ）
           └─ /api/tts        → Aivis Cloud API で返事を音声にする（API キーはサーバー側だけ）
      │
  ③ 1つの AudioContext で「つなぎ言葉 →（必要なら考え中）→ 返事」を順番に再生
  ④ 「あなたの番です」に戻る（生徒が押すまで待つ）
```

| 役割 | 採用 | 理由 |
| --- | --- | --- |
| 音声認識 | ブラウザ標準（webkit） | 無料。⚠ iPad の制限あり（4.1） |
| 返事の文 | Claude `claude-sonnet-5` | ✅ 1往復 1.5〜2.0 秒。無料枠切れで止まらない |
| 返事の声 | Aivis Cloud API | 日本語専用でアクセントが正しい。ローカル版は遅すぎる（3.5） |
| 固定の声（つなぎ言葉など） | 事前に作った音声ファイル | 毎回同じ文言なので API を呼ばない |

## 3. モックで決まったこと

### 3.1 話す順番（押して話す）✅

- AI が話し終えたら **「あなたの番です」で止まる。タイムアウトなし。** 自動でマイクを開かない。
  （自動で開くと、無音で認識が終わり、生徒が答える前に AI が次を話し出す不具合が出た）
- AI が話している間は 🎤 を押せない（AI 自身の声を拾わないため）。
- 🎤 を押して話し、もう一度押して送る。
- 聞き取れなかったときは AI は話さず、「もう一度押してください」と表示するだけ。
- マイクが許可されていないときは、開き直しを繰り返さず案内を出して待つ。
- 1分の上限・混雑などの一時的なエラーでは会話を終わらせない。返事できなかった生徒の発言は履歴から外し、「あなたの番」に戻す。

### 3.2 つなぎ言葉（沈黙を埋める）✅

生徒が話し終えた瞬間に、場面に合う前置きを言い、その裏で返事を作る。

**実測**（ローカル AivisSpeech・返事生成はダミー600ms）

| | 最初の声まで | 途中の沈黙 |
| --- | --- | --- |
| つなぎ無し | 6.3 秒 | — |
| つなぎあり（短い答え） | 0 秒 | 0.5 秒 |
| つなぎあり（長い答え） | 0 秒 | 0.8 秒 |

**ルール**

1. 発言から場面を判定する（AI を使わず規則で一瞬）。暗い話を最優先で拾う。
2. その場面の言葉からランダムに1つ。直近に使った言葉は避ける（ただし候補は常に2つ以上残す。残り1つに固定されると順番が読まれる）。
3. `{名前}` を含む言葉は **4回に1回以下、しかも半分の確率で見送る**（毎回呼ぶと芝居がかる）。
4. AI に「すでに『◯◯』と言った」ことを伝え、続きだけを書かせる（「おおー、いいねー。へえ、いいね」の二重相槌を防ぐ）。
5. つなぎ言葉を言い終えても返事ができていなければ、**400ms 待ってから [考え中] の言葉で2段目**（1回の返事で最大2回）。
6. 声が準備できていない言葉は使わない（その場で作ると逆に遅れる）。場面の言葉が無ければ [ふつう] で代用、それも無ければつなぎ無し。
7. つなぎを使わなかった返事には**理由を表示**（「オフ」「準備が間に合わず（ふつう・準備済み 0/3）」）。

**場面ごとの言葉（初期値）**

| 場面 | 言葉 |
| --- | --- |
| ふつう | うんうん、なるほどねー。／へえー、そうなんだー。／うーん、そっかそっかー。 |
| 考え中 | えーっとねー、／うーんとねー、 |
| みじかい | うんうん。／そっかー。 |
| 楽しい | おおー、いいねー。／へえー、それは楽しそうだねー。／わあ、いいなあー。／{名前}、よかったねー。 |
| 大変 | そっかー、それは大変だったねー。／うーん、そうだったんだー。／あらら、おつかれさまー。 |
| 質問 | うーん、そうだなあー。／おっ、いい質問だねー。 |
| びっくり | えっ、ほんとに？／おおー、すごいじゃん。／さすがは{名前}だねー。 |

**場面の判定（上から順に、最初に当たったもの）**

| 場面 | 当てはまる表現 |
| --- | --- |
| 大変（打ち消し） | 楽し・嬉し・面白・美味し ＋「くな」、よくなかった、できなかった、勝てなかった、好きじゃな、つまらな、つまんな、微妙 |
| 大変 | 疲れ、大変、最悪、嫌だ、嫌い、だるい、怒られ、負けた、落ち込、落ちた、失敗、悲し、つらい、痛い、赤点、ミスし、喧嘩、風邪、熱が、忘れ物、しんどい、むかつ、残念、ダメだった、泣い |
| 質問 | 末尾が「？」、教えて、知ってる、どう思う、どうして、なんで、なぜ、ってなに、わかる？ |
| びっくり | 初めて、びっくり、優勝、一位、合格、満点、100点、選ばれ、キャプテン、新記録、自己ベスト |
| 楽しい | 楽し、嬉し、勝った、よかった、最高、面白、美味し、遊んだ、行ってきた、できた、褒め、好き、ハマって |
| みじかい | 6文字以下 |
| ふつう | それ以外 |

**検証**：「楽しかったけど試合には負けた」→ 大変、「文化祭の準備は楽しくなかった」→ 大変 など13件すべて期待どおり。

### 3.3 プロンプト ✅

**システムプロンプト（初期値）**

```
あなたは学習塾で生徒（中高生）と雑談する、聞き役の大人です。
守ること:
- 返事は原則ひとつの文だけ。長くても25文字以内。話し言葉で。
- 話をもう少し引き出す短い質問を1つだけ返す。
- 長くなりそうなときは説明を捨てて、質問だけに絞る。
- アドバイス、説教、評価、勉強や成績の話への誘導はしない。
- 箇条書き・記号・絵文字・顔文字は使わない（声で読み上げるため）。
- 相手の返事が短いときや黙ったときは、責めずに軽く話題を変える。
声で読み上げられます。書き方を必ず守ってください:
- 記号、絵文字、顔文字、括弧、箇条書き、三点リーダーは使わない。
- 数字と英単語はひらがなカタカナで書く。「5時」ではなく「ごじ」、「OK」ではなく「オッケー」。
- 間を置きたいところに読点を打つ。「へえ、それは楽しそうだね」。
- 語尾は話し言葉らしく伸ばしてよい。「そうなんだ」より「そうなんだー」。
- 文の終わりは「。」か「？」のどちらかで必ず閉じる。
返事の例: 「誰と行ったの？」「それで、どうなったの？」
```

**毎ターン末尾に足す指示**

- つなぎ言葉を言った場合：
  `【このターンの注意】あなたは相手の発言を聞いた直後に、すでに「{つなぎ言葉}」と声に出しています。その続きとして自然につながる部分だけを返してください。相槌や、同じ意味の言葉から始めないでください。`
- 言っていない場合：
  `【このターンの注意】短い相槌をひとこと入れてから返してください。`

**最初のひとこと**：`こんにちは。今日はどんな一日だった？`
聞き取りアプリでは、ここを聞き取りの目的に合わせて変える。

### 3.4 返事の文：Claude API ✅

| 項目 | 値 |
| --- | --- |
| モデル | `claude-sonnet-5` |
| 考える量 | `output_config: { effort: "low" }`（thinking は送らない＝Sonnet 5 では adaptive） |
| max_tokens | 1024（返事は25文字程度。考える分の余裕） |
| 送らないもの | `temperature` / `top_p` / `top_k`（Sonnet 5 では 400 エラー） |
| 会話の形 | `messages` は user から始める。AI の最初のひとことの前に `（生徒が来ました。会話を始めてください）` を user として入れる |
| 実測 | 1往復 1.5〜2.0 秒、入力 約550・出力 約15 トークン |
| 費用目安 | 10往復で約5円 |

**エラーの見分け方と表示**（会話を続けてよいもの＝続行）

| HTTP | 種類 | 表示 | 続行 |
| --- | --- | --- | --- |
| 401 | 認証 | API キーが正しくありません | × |
| 402 | 支払い | クレジット残高か支払い設定に問題 | × |
| 403 | 権限 | このキーでは使えない操作 | × |
| 404 | モデル | モデル名が見つかりません | × |
| 429 | 1分の上限 | ◯秒待ってから話しかけて（retry-after ヘッダー） | ○ |
| 429 | 今月の上限 | `error.details.error_code == "enforced_spend_limit_reached"` のとき | × |
| 400 | リクエスト不正 | 受け付けられませんでした | × |
| 529 | 混雑 | 混み合っています（Python SDK では OverloadedError） | ○ |
| 5xx | サーバー | 一時的なエラー | ○ |
| 接続 | 通信 | 接続できませんでした | ○ |
| 200 | `stop_reason == "refusal"` | 「ごめん、その話はうまく答えられないや。ほかのことも聞かせて？」 | ○ |

**API キーは必ずサーバー側だけで使う。** ブラウザから直接呼ばない。

### 3.5 声（TTS）の選定 ✅

- 多言語 TTS（Gemini TTS / ElevenLabs / OpenAI）は日本語の高低アクセントが崩れ、機械的に聞こえた。声質の問題ではなくアクセント辞書の問題なので、口調指示では直らない。
- AivisSpeech（日本語専用・Style-Bert-VITS2 系）でアクセントは解決。
- ただし**ローカル版（Mac の CPU）は遅い**：12文字で 6.7 秒、同時に2件頼むと返事の声が 36.5 秒。公開アプリでは使えない。
  → 公開アプリでは Aivis Cloud API を推奨（4.3）。

### 3.6 固定の声（最初のひとこと・聞き返し・つなぎ言葉 約20個）✅

- 毎回同じ文言なので**事前に音声を作り、API を呼ばずに再生する。**
- 声（モデル）・速さ・高さ・抑揚を変えたら作り直す（モックでは保存キーにこれらを含めた）。
- モックはブラウザ（IndexedDB）に保存。公開アプリでは管理側で一度作ってストレージ（静的ファイル等）に置き、全端末で共有するのが確実。
- 生成中に返事の声とぶつけない（ローカルでは1件ずつの順番待ち＋返事を優先にした）。

### 3.7 計測表示 ✅

返事ごとに表示：最初の声まで ◯ms ／ つなぎ ◯回（場面）／ 途中の沈黙 ◯ms ／ 考える ◯ms ／ 声を作る ◯ms
つなぎを使わなかったら理由。「遅い」を感想でなく数字で直すために残す。

## 4. 公開アプリで作り直す必要がある点

### 4.1 iPad の音声認識 ⚠ 要実機確認

- iOS/iPadOS の Safari 14.5 以降は `webkitSpeechRecognition` で使える。
- `continuous = true` は iOS では実質使えない（1つの結果が延々と伸びる）。モックの「押している間は自動で開き直す」方式は使わず、**1回の発話ごとに `continuous = false` で開始 → `onend` で確定**にする。
- `interimResults`（途中の文字）は不安定。表示は「聞いています…」程度にとどめる。
- ホーム画面に追加した Web アプリ / アプリ内ブラウザ（WebView）ではエラーになる。**Safari 本体で開く運用**にする。
- 精度や安定性が足りなければ、サーバー側の音声認識に切り替える（別途検討）。

### 4.2 iPad での再生 ⚠ 要実機確認

- Safari はタップから時間がたってからの再生を止める。「つなぎ言葉 → 待つ → 返事」の返事が鳴らない恐れ。
- 「はじめる」のタップで **AudioContext を1つだけ作って `resume()`**、以後はそれを使い回す（1ページ4個まで）。
- 音声は `decodeAudioData` → `AudioBufferSourceNode` で再生し、`new Audio()` を毎回作らない（モックはこの方式なので要変更）。
- 再生は1本の列にし、前の音が終わってから次を鳴らす（重ねない）。

### 4.3 Aivis Cloud API ⚠ 要実機確認（項目は公式の openapi.json で確認済み）

> **いまは使わない方針。** PC のローカル AivisSpeech に切り替えた（`HANDOVER.md` 参照）。
> 将来クラウドに戻すときのために原文を残す。

- `POST https://api.aivis-project.com/v1/tts/synthesize`
- ヘッダー：`Authorization: Bearer {APIキー}`、`Content-Type: application/json`
- 返り値：音声がストリーミングで順番に届く（全部そろう前から再生を始められる）

| 項目 | 指定 | メモ |
| --- | --- | --- |
| model_uuid | 必須 | 付録A |
| style_name | 例 `"おちつき"` | style_id（0〜31）とどちらか一方だけ |
| text | 必須 | 最大3000文字 |
| use_ssml | `false` を推奨 | 初期値は true。記号を SSML タグと誤解釈させない |
| language | `"ja"` | 現在は日本語のみ |
| speaking_rate | 0.5〜2.0（初期 1.0） | モックの「速さ」に相当 |
| emotional_intensity | 0.0〜2.0（初期 1.0） | 感情の強さ。モックの「抑揚の強さ」に近い |
| tempo_dynamics | 0.0〜2.0（初期 1.0） | モックの「抑揚の動き」。上げると早口で生っぽい抑揚 |
| pitch | -1.0〜1.0（初期 0.0） | 声の高さ |
| leading_silence_seconds | 初期 0.1 | 先頭の無音。0.05 程度に削ると食い気味で自然（モックの設定） |
| trailing_silence_seconds | 初期 0.1 | 末尾の無音（モックは 0.15） |
| output_format | mp3 か aac | 初期値 mp3。opus は iOS 18.4 以降のみ、wav はデータが大きい |
| output_sampling_rate | 初期 44100 | 通信が遅い環境では 24000 に下げる |

エラー：401 キーが無効／402 クレジット不足／404 モデルが見つからない／422 パラメータ不正／429 レート制限／500〜504 サーバー
3.4 と同じ考え方で、429・5xx は会話を続けて「少し待って」と表示、それ以外は止める。

- 詳細な仕様：https://api.aivis-project.com/v1/docs
- 料金：従量課金 440円／1万文字、Aivisプレミアム 1,980円／月（文字数無制限・1分10リクエストまで）。新規登録で500円分（約11,000文字）
- 公式の速度：ストリーミングで再生開始まで最速約0.3秒
- データ：国内サーバーで処理、AI の学習には使わないと明記
- 1分10回の制限があるので、固定の声は必ず事前生成。API を呼ぶのは返事だけ（1往復1回）。
- API キーはサーバー側だけ。

### 4.4 目標の時間

生徒が話し終える → つなぎ言葉 0秒 → 返事（Claude 約2秒 ＋ Aivis Cloud 約0.3〜0.7秒）
**途中の沈黙を1秒未満にするのが目標。** 計測表示で確認する。

## 5. 個人情報と運用（生徒は未成年）

- **会話の本文をサーバーのログに残さない。** モックのサーバーは、モデル名・トークン数・時間だけを記録している。
- 会話を保存するなら、何を・どれだけの期間保存するかを先に決め、保護者の同意を取る。
- API キーはホスティングの環境変数に置く。ブラウザ・リポジトリ・チャットに置かない。
- サーバーの API を誰でも呼べる状態にしない（スタッフのログインなどの認証＋回数制限）。公開 URL のままだとクレジットを他人に使われる。
