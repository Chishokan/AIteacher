## 1. このアプリは何か

タブレットのアバターが音声で質問し、生徒が声で答えるアプリ。学習塾（智翔館）で使う。
機能は**2つ**あり、**互いに独立**している。

| 機能 | 状態 | 入口 |
| --- | --- | --- |
| **定期テストの聞き取り** | 完成。実運用の検証段階 | 最初の画面「はじめる」 |
| **雑談** | 作りかけ（実装順 3/7 まで） | 最初の画面「💬 雑談してみる」 |

### いちばん大事な制約

**雑談の作業で、定期テストの聞き取りを壊さないこと。** 利用者からの明示の指示。

そのため、次のファイルには触れない方針で進めてきた。触る必要が出たら、
理由を説明したうえで回帰確認（第 6 章）を必ず行うこと。

```
src/hooks/useInterview.ts    聞き取りの進行
src/logic/parseAnswer.ts     答えの解釈
src/logic/interview.ts       復唱文・集計・CSV
src/data/scenario.ts         質問の並び
src/speech/clips.ts          事前生成した音声の再生
src/speech/tts.ts            ブラウザの読み上げ
```

いまのところ、雑談のために既存側へ入れた変更は 2 つだけ。

- `src/logic/settings.ts` に `chat*` の項目を追加（追加のみ）
- `src/speech/stt.ts` の `getRecognitionCtor` に `export` を付けた（挙動は不変）

## 2. 動かし方（PC）

利用者の環境は **Mac**。PC だけで完結するよう作ってある。デプロイはまだしていない。

```bash
npm install
cp .env.example .env.local     # ANTHROPIC_API_KEY を書く
npm run dev                    # http://localhost:5173
```

- **`localhost` で開くこと。** `192.168.x.x` だとマイクがブロックされる
- **AivisSpeech アプリを起動しておくこと。** 雑談の声はローカルの
  AivisSpeech Engine（`http://127.0.0.1:10101`）に作らせる。**クラウド API は使わない**（利用者の指示）
- 起動時に出る 2 行で、キーとエンジンの状態が分かる

```
➜  雑談 API: /api/voice-chat  ANTHROPIC_API_KEY を読み込みました
➜  音声 API: /api/tts  AivisSpeech = http://127.0.0.1:10101
```

API キーは `.env.local` にだけ置く。`vite.config.ts` の `loadEnv` で読み、
サーバー側のプラグインにしか渡らない（ビルド成果物に出ないことを確認済み）。
**キーをチャットやリポジトリに貼らないこと。**

## 3. これまでに決めたこと（理由つき）

コードだけ見ても分からない判断。**勝手に戻さないこと。**

### 定期テストの聞き取り

| 決めたこと | 理由 |
| --- | --- |
| 既定は**定期テストの得点だけ**（準備確認 1 問＋教科ぶん） | 収録した音声の範囲に合わせた。通知表・ふりかえり・次の目標は設定でオン |
| 確認では**答えの値を読み上げない**。「こちらの点数であっていますか。」と言い、値は画面に大きく出す | 値を読むと点数ぶん（101 本）の音声が要る |
| 確認するのは**得点と評定だけ**。選択肢と自由記述は確認しない | 聞き間違いが記録に残ると困るのは数値だけ |
| 教科別の言い直しを廃止し、**`again.mp3`「ごめんなさい。もう一度お願いします。」に統一** | 教科を増やすたびに音声が増えるのを避ける |
| 導入の音声は通知表のオン／オフで**2 種類を使い分ける** | 文言が変わるため。`q-intro-ready`（通知表あり）と `q-intro-ready2`（なし） |
| 音声が置かれていない文言は**ブラウザの読み上げに落ちる** | 段階的に差し替えられるように |
| マイク許可は**「はじめる」のタップの中で `getUserMedia`** を呼んで取る | 読み上げ後に音声認識が始まるころには、ブラウザが「操作の直後」とみなす時間（Chrome は 5 秒）を過ぎていて、許可ダイアログが出ないまま不許可で進んでいた（スマホで発覚） |
| それでも認識を始められない端末向けに**「タップして話す」**を大きく出す | iOS Safari 対策 |

### 雑談

| 決めたこと | 理由 |
| --- | --- |
| **別メニュー**にし、進行も画面も聞き取りと共有しない | 聞き取りを壊さないため（利用者の指示） |
| 音声認識は**押して話す**。自動でマイクを開かない。時間による打ち切りもしない | 自動だと無音で認識が終わり、生徒が答える前に AI が話し出す（モックでの知見） |
| 聞き取れなかったら**アバターは話さない**。押し直しの案内だけ | 同上 |
| 声は**ローカルの AivisSpeech**。クラウド API は使わない | 利用者の指示 |
| 再生は **AudioContext を 1 つ使いまわす**。`new Audio()` を毎回作らない | Safari はタップから時間がたった再生を止める |
| AivisSpeech が落ちていても**会話は止めない**。ブラウザの読み上げに落として画面に理由を出す | 検証中に止まると困る |
| 返事の作り手は `ReplySource`、声は `Voice` という**境目**で切ってある | 差し替えても画面と進行が変わらないようにするため |

### Claude API（`server/voiceChat.ts`）

利用者が持ち込んだ引き継ぎ仕様の指定どおり。**現行 API と整合していることを確認済み。**

- モデル `claude-sonnet-5`、`output_config: { effort: 'low' }`、`max_tokens: 1024`
- **`thinking` は送らない**（Sonnet 5 では adaptive になる）
- **`temperature` / `top_p` / `top_k` は送らない**（送ると 400）
- **毎ターンの注意は、top-level の `system` ではなく最後の user メッセージの末尾に足す。**
  Sonnet 5 は会話途中の `system` ロールに対応しておらず、`system` を毎ターン
  書き換えると前置きのキャッシュが効かなくなるため
- `messages` は user から始める。アバターの最初のひとことの前に
  `（生徒が来ました。会話を始めてください）` を user として入れる
- エラーは**「続けてよいもの」と「止めるもの」**に振り分ける（`describeError`）。
  続行のときは、返事できなかった生徒の発言を履歴から外して「あなたの番」に戻す
- **会話の本文はログに残さない**（生徒は未成年）。モデル名・トークン数・時間だけ

### AivisSpeech（`server/aivis.ts`）

- VOICEVOX 互換 HTTP API。`/audio_query` → 設定を書き換え → `/synthesis` → WAV（24kHz）
- **スタイル ID は決め打ちにしない。** エンジンが speaker UUID から作るもので固定ではないため、
  `/speakers` から毎回引く
- AivisSpeech で意味が変わる項目：`intonationScale` は「感情表現の強さ」。
  `tempoDynamicsScale` は AivisSpeech 独自。`prePhonemeLength` などは無視される
- `pitchScale` は 0 から動かすと音が荒れることがある

## 5. 次にやること

引き継ぎ仕様の実装順。**1〜3 は完了。次は 4。**

### ステップ4：固定の声の事前生成 ← いまここ

**利用者の承認済み。**「最初に流れる音声は事前に生成したものを使用する」

いまは雑談の最初のひとことも毎回 AivisSpeech に作らせているため、画面を開いてから
声が出るまで数秒かかる（Mac の CPU で 12 文字 6.7 秒という実測がある）。
毎回同じ文言のものは先に作って置いておく。

対象（毎回同じ文言のもの）

- 雑談の最初のひとこと（`settings.chatOpening`）
- 聞き返しの案内「うまく聞き取れませんでした。もう一度押してください。」
- つなぎ言葉 約 20 個（ステップ 5 で使う。第 5.2 節）

やり方の案

1. `scripts/gen-chat-audio.mjs` を作り、ローカルの AivisSpeech を叩いて
   `public/audio/chat/` に WAV（か MP3）を書き出す
2. **声・速さ・高さ・抑揚を変えたら作り直す。** モックでは保存キーにこれらを含めていた。
   同じ考えで、ファイル名か横に置く JSON に条件を残し、設定と食い違ったら
   その場合成に落とすか、作り直しを促す
3. `src/chat/voice.ts` に「事前生成があればそれを鳴らし、無ければその場で作る」を足す
4. 生成中に返事の声とぶつけない。ローカルは 1 件ずつの順番待ちで、返事を優先する

完了の目安：雑談を開いた瞬間に最初のひとことが鳴る（待ち 0 秒）。

### ステップ5：つなぎ言葉

場面の判定表・言葉の一覧・二重相槌の防ぎ方は、**`docs/voice-chat-spec.md` の第 3.2 節**に
全部載せてある（利用者から受け取った原文をそのまま置いたもの）。貼ってもらう必要はない。

要点だけ：発話から場面を規則で判定（AI は使わない）→ その場面の言葉を鳴らす →
裏で返事を作る → 「すでに『◯◯』と言った」を Claude に伝えて続きだけ書かせる。
`server/prompts.ts` の `turnInstruction(filler)` は**すでに対応済み**。
`/api/voice-chat` も `filler` を受け取れる。画面の計測欄も
「つなぎ ◯回（場面）」「途中の沈黙 ◯ms」の枠を用意してある。

場面の判定は**純粋な関数**になるので、必ず単体テストを書くこと。
`docs/voice-chat-spec.md` 第 3.2 節に検証済みの 13 件の例がある。

## 6. 変更したら必ず確認すること

**定期テストの聞き取りが壊れていないこと**を毎回見る。方法は
ヘッドレスの Chromium で実際に画面を操作する。

```bash
npm test          # 単体テスト 31 件
npm run build     # 型チェック込み
```

ブラウザでの確認は Playwright を使ってきた。音声合成と音声認識を差し替えて
（`page.addInitScript` で `window.speechSynthesis` と `window.SpeechRecognition` を
置き換える）通しで動かす。確認してきた項目：

- 聞き取り：20 問を最後まで、結果の集計、CSV、縦向きで横スクロールしないこと
- 音声：用意した音声が鳴り、無いものだけ読み上げに落ちること
- 設定：通知表をオンにすると質問が 6 問 → 17 問に増えること
- マイク：「はじめる」で `getUserMedia` が呼ばれること、拒否時の表示
- 雑談：放置しても進まないこと、話している間は押せないこと、
  聞き取れないときに喋らないこと、AivisSpeech が落ちていても続くこと

**AivisSpeech が無い環境で試すとき**は、疑似エンジンを立てると通しで確認できる。
`/speakers` `/audio_query` `/synthesis` の 3 つを返す小さなサーバーで足りる。
