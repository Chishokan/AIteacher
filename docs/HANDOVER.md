## 1. このアプリは何か

タブレットのアバターが音声で質問し、生徒が声で答えるアプリ。学習塾（智翔館）で使う。
機能は**3つ**。定期テストの聞き取りと、あとの 2 つは**互いに独立**している。
コーチングタイムと雑談は、同じしくみを使い回している。

| 機能 | 状態 | 入口 |
| --- | --- | --- |
| **定期テストの聞き取り** | 完成。実運用の検証段階 | 最初の画面「はじめる」 |
| **雑談** | 作りかけ（実装順 5/7 まで） | 最初の画面「💬 雑談してみる」 |
| **コーチングタイムの聞き取り** | 作りかけ。東進高校生部門で検討中 | 最初の画面「📋 コーチングタイムの聞き取り」 |

コーチングタイムは**雑談と同じしくみ**（押して話す・つなぎ言葉・AivisSpeech・
キャラクター）で動く。違うのは**聞くことが決まっている**ところだけ。第 4 章を参照。

### いちばん大事な制約

**雑談の作業で、定期テストの聞き取りを壊さないこと。** 利用者からの明示の指示。

そのため、次のファイルには触れない方針で進めてきた。触る必要が出たら、
理由を説明したうえで回帰確認（第 6 章）を必ず行うこと。

```
src/hooks/useInterview.ts    聞き取りの進行
src/logic/parseAnswer.ts     答えの解釈
src/logic/interview.ts       復唱文・集計・CSV
src/data/scenario.ts         質問の並び
src/speech/clips.ts          事前生成した音声の再生
src/speech/tts.ts            ブラウザの読み上げ
```

いまのところ、雑談のために既存側へ入れた変更は次の 4 つだけ。

- `src/logic/settings.ts` に `chat*` の項目を追加（追加のみ）。
  声まわりの初期値は `src/chat/voiceDefaults.ts` から取るようにした（値は同じ）
- `src/speech/stt.ts` の `getRecognitionCtor` に `export` を付けた（挙動は不変）
- `server/aivis.ts` の `AivisEngineError` を、引数に `readonly` を付ける書き方から
  ふつうのフィールドに直した（挙動は不変）
- `src/App.tsx` と `src/components/StartScreen.tsx`：「💬 雑談してみる」が
  名前を渡すようにした。つなぎ言葉の「{名前}」に使う。
  **聞き取り側の `studentName` とは別の状態**（`chatStudentName`）に入れてあるので、
  聞き取りの進行には影響しない

## 2. 動かし方（PC）

利用者の環境は **Mac**。PC だけで完結するよう作ってある。デプロイはまだしていない。

```bash
npm install
cp .env.example .env.local     # ANTHROPIC_API_KEY を書く
npm run dev                    # http://localhost:5173
```

- **`localhost` で開くこと。** `192.168.x.x` だとマイクがブロックされる
- **AivisSpeech アプリを起動しておくこと。** 雑談の声はローカルの
  AivisSpeech Engine（`http://127.0.0.1:10101`）に作らせる。**クラウド API は使わない**（利用者の指示）
- 起動時に出る 2 行で、キーとエンジンの状態が分かる

```
➜  雑談 API: /api/voice-chat  ANTHROPIC_API_KEY を読み込みました
➜  音声 API: /api/tts  AivisSpeech = http://127.0.0.1:10101
```

**雑談を使う前に、1 度だけ音声を作っておくこと。** 毎回同じ文言（最初のひとこと・
つなぎ言葉）を先に作っておくと、画面を開いた瞬間に声が出る。
**つなぎ言葉は、音声が用意できていないと 1 つも鳴らない。**

```bash
npm run gen:chat-audio                 # AivisSpeech を起動してから（19 本）
npm run gen:chat-audio -- --check      # そろっているかだけ見る
npm run gen:chat-audio -- --name ゆうと # 名前入りのつなぎ言葉も作る（21 本）
```

作った音声は `public/audio/chat/` に入る。**git には入れていない**（作り直せるため）。
設定画面で声や速さを変えたら、同じ条件で作り直すこと。作り直さなくても壊れないが、
その場合成にもどるので遅くなる。

API キーは `.env.local` にだけ置く。`vite.config.ts` の `loadEnv` で読み、
サーバー側のプラグインにしか渡らない（ビルド成果物に出ないことを確認済み）。
**キーをチャットやリポジトリに貼らないこと。**

## 3. これまでに決めたこと（理由つき）

コードだけ見ても分からない判断。**勝手に戻さないこと。**

### 定期テストの聞き取り

| 決めたこと | 理由 |
| --- | --- |
| 既定は**定期テストの得点だけ**（準備確認 1 問＋教科ぶん） | 収録した音声の範囲に合わせた。通知表・ふりかえり・次の目標は設定でオン |
| 確認では**答えの値を読み上げない**。「こちらの点数であっていますか。」と言い、値は画面に大きく出す | 値を読むと点数ぶん（101 本）の音声が要る |
| 確認するのは**得点と評定だけ**。選択肢と自由記述は確認しない | 聞き間違いが記録に残ると困るのは数値だけ |
| 教科別の言い直しを廃止し、**`again.mp3`「ごめんなさい。もう一度お願いします。」に統一** | 教科を増やすたびに音声が増えるのを避ける |
| 導入の音声は通知表のオン／オフで**2 種類を使い分ける** | 文言が変わるため。`q-intro-ready`（通知表あり）と `q-intro-ready2`（なし） |
| 音声が置かれていない文言は**ブラウザの読み上げに落ちる** | 段階的に差し替えられるように |
| マイク許可は**「はじめる」のタップの中で `getUserMedia`** を呼んで取る | 読み上げ後に音声認識が始まるころには、ブラウザが「操作の直後」とみなす時間（Chrome は 5 秒）を過ぎていて、許可ダイアログが出ないまま不許可で進んでいた（スマホで発覚） |
| それでも認識を始められない端末向けに**「タップして話す」**を大きく出す | iOS Safari 対策 |

### 雑談

| 決めたこと | 理由 |
| --- | --- |
| **別メニュー**にし、進行も画面も聞き取りと共有しない | 聞き取りを壊さないため（利用者の指示） |
| 音声認識は**押して話す**。自動でマイクを開かない。時間による打ち切りもしない | 自動だと無音で認識が終わり、生徒が答える前に AI が話し出す（モックでの知見） |
| 聞き取れなかったら**アバターは話さない**。押し直しの案内だけ | 同上 |
| 声は**ローカルの AivisSpeech**。クラウド API は使わない | 利用者の指示 |
| 再生は **AudioContext を 1 つ使いまわす**。`new Audio()` を毎回作らない | Safari はタップから時間がたった再生を止める |
| AivisSpeech が落ちていても**会話は止めない**。ブラウザの読み上げに落として画面に理由を出す | 検証中に止まると困る |
| 返事の作り手は `ReplySource`、声は `Voice` という**境目**で切ってある | 差し替えても画面と進行が変わらないようにするため |
| 毎回同じ文言は**先に音声にして置いておく**。無ければその場で作る | その場で作ると数秒かかる。置いてあれば待ち 0 秒 |
| 事前生成と現物の突き合わせは、ID ではなく**「文言＋声の条件」の一致**で見る | 最初のひとことは設定で変えられる。ID だと、文言を変えたのに古い音声が鳴る |
| 条件が食い違ったら**黙ってその場合成に落とす**。エラーにしない | 設定を変えた直後に雑談が使えなくなるほうが困る |
| 事前生成した音声は **git に入れない**（`public/audio/chat/`） | 声の設定しだいで中身が変わる。`npm run gen:chat-audio` で作り直せる |
| 聞き返しの案内も音声を作ってあるが、**まだ鳴らしていない** | 「聞き取れなかったらアバターは話さない」を変えていないため。鳴らすかは別の判断 |
| つなぎ言葉は、**事前生成があるものしか使わない**。ただしブラウザの読み上げのときは全部使う | その場で作ると逆に遅くなる（仕様 3.2 の 6）。読み上げは待ち時間が無いので制限する理由がない |
| つなぎ言葉の「{名前}」は、**最初の画面で名前を入れたときだけ**使える | 名前入りの音声は名前を決めないと作れない。`--name` で作り、同じ名前で開いたときだけ一致する |
| 名前は聞き取り側と**別の状態**で持つ（`chatStudentName`） | 聞き取りの進行に影響させないため |
| 返事づくりを**先に走らせてから**つなぎ言葉を鳴らす | 逆にすると、つなぎ言葉を言い終えてから考え始めることになり、沈黙が伸びる |
| アバターに**キャラクター設定**を持たせ、自分のことも話させる | 仕様 3.3 の指示文は「聞き役」に振り切っていて、毎回おうむ返し＋質問になっていた（利用者の指摘） |
| **毎回は質問しない。** 返し方を回ごとに変える（質問／自分の話／受けとめるだけ／答える） | 同上。型を決め打ちにすると一本調子になる |
| 返し方は**乱数を使わず、何回目かで決める** | 同じ流れなら同じ結果になり、単体テストで確かめられる。場面判定と同じ考え方 |
| 長さを広げるのは**自分の話をする回と答える回だけ**。ふだんは 1 文・25 文字のまま | 長いほど声を作るのに時間がかかる（ローカルは 12 文字で 6.7 秒）。全部広げると沈黙が伸びる |
| **していない体験は語らせない。** AI であることも隠さない | 生徒は中高生。作り話を本当のことと受け取られると困る |
| キャラクター設定は**サーバー側（`server/persona.ts`）だけ**に置く。設定画面には出さない | 置き場所を 2 つに分けると食い違う。生徒が最初の画面から設定を開けるので、人格を書き換えられる状態にもしたくない |
| **5 回のやりとりで 1 セット。** 話し終えるとアバターが締め、勝手には続かない | 利用者の指示。いつまでも続くと、聞き取りの前のアイスブレイクにならない |
| 何回で区切るかは**ブラウザ側が決め**、`closing` としてサーバーに渡す | 会話の進行はブラウザが持っている。サーバーは「どう言うか」だけを持つ |
| 締めたあとは**「もう少し話す」を押せば続けられる**。話した内容は覚えたまま | 「一旦」完結であって、打ち切りではない |

### コーチングタイム（東進高校生部門）

| 決めたこと | 理由 |
| --- | --- |
| **質問の文言は AI に作らせない。** `coaching/agenda.ts` に固定し、そのまま読み上げる | 塾の決まった項目なので毎回同じ言い方で聞きたい。文言が決まっていれば音声も先に作れる |
| AI にさせるのは**受けとめと、その話題の中の短い深掘りだけ** | 次に何を聞くかを AI に任せると、項目が抜けたり順番が変わったりする |
| 話題の最後は「受けとめるだけ」にして、**そのあと次の質問を続けて言う** | AI に話題を変えさせない。切り替えの言い方も毎回同じになる |
| 進め方（何番目の話題か・次に何を言うか）は**副作用のない関数**にした（`coaching/plan.ts`） | 進行のいちばん大事なところ。単体テストで確かめられるようにするため |
| 指示文は雑談と**別にした**（`buildCoachingPrompt`）。評価・説教・アドバイスを禁止 | 実行率が低いときに責められると、次から正直に答えなくなる |
| 実行率は**読み取れなければ null。** 無理に数字にしない | 記録に嘘が残るほうが困る。聞き取った言葉はそのまま残してある |
| 記録は**項目と生徒の答えだけ。** アバターの発言ややりとりは残さない | 第 7 章「会話を保存するか」が未決。聞き取りの結果として要る分にとどめた |
| 記録の置き場は定期テストとは**別の鍵**（`aitecher.coaching.v1`） | 片方を消しても、もう片方に影響しない |
| 1 項目めだけ 2 回、2 項目めは 1 回…と**項目ごとに回数を変えた**（合計 6 回） | 全部 2 回にすると長い。実行率と不安なことは掘りたいが、講座の予定は確認だけでよい |

### 生徒名簿との照らし合わせ

| 決めたこと | 理由 |
| --- | --- |
| **スプレッドシートから貼り付けるだけで使える**ようにした。Supabase は任意 | 校舎がいまスプレッドシートで管理している。設定なしで今日から試せるほうが早い |
| 列の順番は決め打ちにせず、**1 行目の見出しで対応づける** | 校舎ごとに並びや呼び方が違う。「次回来校日」と「来校状況」のような紛らわしい見出しは、長いほうから当てる |
| 生徒の照合は**東進ID（固有ID）が本命。** 名前は当たらなかったときの受け皿 | 利用者の指示。同姓や表記ゆれがあっても取り違えない。名前だけだと、同姓が 2 人いると当てられない |
| **東進ID は数字だけ。** 突き合わせるときは数字以外を落とす | 利用者に確認済み。全角で入れられても、「No.」やハイフンが混ざっても当たる。入力欄も数字しか入らないようにした |
| 表計算ソフトで先頭の 0 が落ちた場合（0101 → 101）も当てる。ただし**2 人以上に当たるなら当てない** | ID を数値として保存すると 0 が落ちる。取り違えるくらいなら、見つからないほうがよい |
| 東進ID を入れると、**名前を名簿から自動で入れる** | 入力の手間が減り、打ち間違いによる取り違えも防げる |
| 記録にも**東進ID を残す** | あとから表計算ソフトで名簿に突き合わせ直せる |
| Supabase の鍵は**サーバー側だけ**。ブラウザは `/api/students` を呼ぶ | 鍵をブラウザに置くと、公開したときに名簿を誰でも引けてしまう |
| 名簿の組み立ては、貼り付けた表も Supabase の行も**同じ関数**に集めた | 出どころが増えても読み方が食い違わない。単体テストも 1 か所で済む |
| **食い違いを「間違い」とは書かない。** 並べて出すだけ | 名簿が古いことも、聞き取りがうまくいっていないこともある。判断はコーチがする |
| 名簿にいない生徒でも、**聞き取りは止めない** | 転入直後や名簿の更新前でも使えるようにする |
| アバターに渡すのは**名簿から分かる事実だけ**。「ここに無いことは言わない」「決めつけない」も指示に入れた | 推測で「数学が遅れてるよね」と言われると、生徒は不信感を持つ |
| 志望校や成績で**励ましたり急かしたりさせない** | コーチングタイムの聞き役という役どころから外れる |
| 名簿はこの端末の中だけに置く（`aitecher.roster.v1`） | 個人情報。公開するときの扱いは第 7 章とあわせて決める |

### Claude API（`server/voiceChat.ts`）

利用者が持ち込んだ引き継ぎ仕様の指定どおり。**現行 API と整合していることを確認済み。**

- モデル `claude-sonnet-5`、`output_config: { effort: 'low' }`、`max_tokens: 1024`
- **`thinking` は送らない**（Sonnet 5 では adaptive になる）
- **`temperature` / `top_p` / `top_k` は送らない**（送ると 400）
- **毎ターンの注意は、top-level の `system` ではなく最後の user メッセージの末尾に足す。**
  Sonnet 5 は会話途中の `system` ロールに対応しておらず、`system` を毎ターン
  書き換えると前置きのキャッシュが効かなくなるため
- `messages` は user から始める。アバターの最初のひとことの前に
  `（生徒が来ました。会話を始めてください）` を user として入れる
- エラーは**「続けてよいもの」と「止めるもの」**に振り分ける（`describeError`）。
  続行のときは、返事できなかった生徒の発言を履歴から外して「あなたの番」に戻す
- **会話の本文はログに残さない**（生徒は未成年）。モデル名・トークン数・時間だけ

### AivisSpeech（`server/aivis.ts`）

- VOICEVOX 互換 HTTP API。`/audio_query` → 設定を書き換え → `/synthesis` → WAV（24kHz）
- **スタイル ID は決め打ちにしない。** エンジンが speaker UUID から作るもので固定ではないため、
  `/speakers` から毎回引く
- AivisSpeech で意味が変わる項目：`intonationScale` は「感情表現の強さ」。
  `tempoDynamicsScale` は AivisSpeech 独自。`prePhonemeLength` などは無視される
- `pitchScale` は 0 から動かすと音が荒れることがある

## 4. いまの構成

```
src/
├── hooks/useInterview.ts     聞き取りの進行（雑談とは無関係）
├── speech/                   聞き取り側の音声まわり
│   ├── stt.ts                打ち切りありの聞き取り
│   ├── tts.ts                ブラウザの読み上げ
│   ├── clips.ts              事前生成した音声の再生（new Audio 方式）
│   └── mic.ts                マイク許可
├── coaching/                 コーチングタイムの聞き取り（東進高校生部門）
│   ├── agenda.ts             聞く 4 項目と質問の文言（**変えるならここ**）
│   ├── plan.ts               何番目の話題か、次に何を言うか（副作用なし）
│   ├── parseRate.ts          「8割」「半分くらい」を実行率にする（副作用なし）
│   ├── record.ts             記録の組み立てと CSV
│   └── storage.ts            記録の置き場（定期テストとは別の鍵）
├── students/                 生徒名簿（スプレッドシート / Supabase）
│   ├── types.ts              名簿の形
│   ├── parseRoster.ts        貼り付けた表・Supabase の行を名簿にする（副作用なし）
│   ├── match.ts              名前・講座・来校予定日の照らし合わせ（副作用なし）
│   ├── facts.ts              アバターに渡す事実の文（副作用なし）
│   └── source.ts             名簿の出どころ（端末 / サーバー経由の Supabase）
├── chat/                     雑談。コーチングタイムもここのしくみを使う
│   ├── types.ts              ターン・計測の型
│   ├── pushToTalk.ts         押して話す聞き取り（打ち切りなし）
│   ├── reply.ts              ReplySource の口。ダミー実装もここ
│   ├── apiReplySource.ts     /api/voice-chat を呼ぶ
│   ├── voice.ts              Voice の口。AivisSpeech とブラウザ読み上げ
│   ├── prebuiltClips.ts      事前生成した音声を探す（文言＋声の条件で突き合わせ）
│   ├── fillers.ts            つなぎ言葉。場面の判定と言葉選び（副作用なし）
│   ├── fixedLines.ts         毎回同じ文言の一覧（最初のひとこと・案内・つなぎ言葉）
│   ├── voiceDefaults.ts      声の初期値。生成スクリプトが Node から直に読む
```

### ステップ5：つなぎ言葉（完了）

### 番外：キャラクターと返し方、5 回 1 セット（実装順の外。利用者の指示で入れた）

「おうむ返し＋新しい質問の一辺倒」を直すために、仕様 3.3 の指示文を 2 か所変えた。

**キャラクターを変えるには `server/persona.ts` の `DEFAULT_PERSONA` を直す。**
名前・一人称・どんな相手か・好きなもの の 4 つだけ。ほかは触らなくてよい。

```ts
export const DEFAULT_PERSONA: ChatPersona = {
  name: 'ミライ',
  firstPerson: 'わたし',
  character: '塾にいる、話し好きのアシスタント。AIであることは隠さないが、…',
  likes: '星や宇宙の話、雨の音、寒い日の自動販売機、…',
}
```

**5 回のやりとりで 1 セット。** 5 回目でアバターが話をまとめて「またね」と締め、
そこで止まる。勝手には続かない。「もう少し話す」を押すと、話した内容を覚えたまま次のセットに入る。
回数は設定画面の「1 セットのやりとり（回）」で変えられる（1〜20）。

**返し方は回ごとに変わる**（`server/replyStyle.ts`）。乱数は使わず、何回目かで決まる。

| 何回目の返事 | 返し方 |
| --- | --- |
| 1・2 回目 | 質問（まず生徒の話を引き出す） |
| 3 回目 | 自分のことを一言そえる（質問しない） |
| 4 回目 | 質問 |
| 5 回目 | **締め**（話を広げず「またね」。セットの最後だから） |
| 以降（もう少し話す） | 受けとめるだけ → 質問 → 自分の話 → 質問 → 締め |

生徒から聞かれた回（つなぎ言葉の場面判定が「質問」）は、何回目でも「まず答える」に切り替わる。
場面はブラウザ側で判定し、`/api/voice-chat` に `scene` として渡している。
**ただしセットの最後だけは締めが優先。** 聞かれたまま終わらないよう、締めの言葉の中で
ひとこと答えるように指示している。

**長さは回ごとに違う。** ふだんは仕様どおり 1 文・25 文字以内。
自分のことを話す回と答える回だけ 2 文・40 文字まで。
全部の回を長くすると、声を作る時間がそのぶん伸びて沈黙が長くなるため。

## 6. 変更したら必ず確認すること

**定期テストの聞き取りが壊れていないこと**を毎回見る。方法は

  聞き取れないときに喋らないこと、AivisSpeech が落ちていても続くこと
- 雑談：事前生成があれば `/api/tts` を呼ばないこと、無ければ落ちて鳴ること
- 雑談：つなぎ言葉が場面どおりに鳴ること、2 段目が出ること、切ると使わないこと
- 雑談：判定した場面が `/api/voice-chat` に渡ること（返し方の切り替えに使う）
- 雑談：5 回で締めること、そこで止まること、「もう少し話す」で続けられること
- コーチング：4 項目を決まった文言で順に聞くこと、6 回で終わること、
  実行率が数字になること、記録が定期テストとは別の鍵で残ること
- 名簿：貼り付けた表を読み取ること、Supabase からも読めること、
  コーチングで引き当てて照らし合わせること、名簿にいなくても止まらないこと
- 東進ID：入れると名前が入ること、同姓がいても取り違えないこと、記録に残ること

**AivisSpeech が無い環境で試すとき**は、疑似エンジンを立てると通しで確認できる。
`/speakers` `/audio_query` `/synthesis` の 3 つを返す小さなサーバーで足りる。
